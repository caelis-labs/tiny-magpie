# tiny-magpie 0.1.1 Preview

First public release of the MIT-licensed reduction fork of [yetone/magpie](https://github.com/yetone/magpie), integrated through `d783df46cbac9021e26a6bd71ca0b55544552eb2`.

- Keep the multi-Provider model gateway, original model protocols and routing, Provider/subscription plugins, and a focused desktop/Web GUI.
- Remove Agent management, Library, session browsing, cloud sync, intent routing, extra media/search/public MCP services and upstream application updates.
- Use independent tiny-magpie configuration, caches and OS identities. Do not share an original Magpie profile. If port 3425 is occupied, set `MAGPIE_ADDR` to another port.
- Follow upstream weekly through an inventory and an actionable sync issue; integrations still require scope and compatibility checks.

Desktop and headless CLI archives are provided for macOS, Linux and Windows, each on amd64 and arm64. Each archive includes MIT LICENSE, UPSTREAM.json and BUILD.json. The release also includes per-platform build evidence and SHA256SUMS.

macOS app and CLI use the organization's Developer ID certificate and Apple notarization. The app has a stapled ticket; the standalone CLI uses Apple's online ticket. Windows and Linux artifacts are unsigned. Windows desktop uses the system WebView2 runtime. Linux desktop is built on Ubuntu 24.04 and requires GTK 3 and WebKitGTK 4.1 (`libgtk-3-0t64`, `libwebkit2gtk-4.1-0`); the CLI/Web build does not need these desktop libraries.

Unpack the desktop archive and open tiny-magpie.app on macOS, tiny-magpie.exe on Windows, or tiny-magpie on Linux. In the CLI archive, run `tiny-magpie serve` for the gateway or `tiny-magpie web --no-open` for Web management.

This is an experimental release. Automated evidence covers the full Go suite on three operating systems, six headless builds, native desktop builds, the 64-case upstream binary protocol differential, 22 Chromium/WebKit GUI cases, and isolated amd64/arm64 container smoke tests. It does not establish real Provider-account acceptance, native Windows/Linux interaction, clean-machine installation, or Caelis/Bot end-to-end use. See [compatibility evidence](https://github.com/caelis-labs/tiny-magpie/blob/main/docs/compatibility.md) before production use.

The `tiny-v0.1.0` candidate was not published: its Windows settings concurrency fixture used a reader that did not wait for a known file temporarily hidden by replacement. This release uses the existing known-file reader in that fixture and keeps every save, field-preservation and complete-JSON assertion. Production code and retained protocols are unchanged from that candidate.
