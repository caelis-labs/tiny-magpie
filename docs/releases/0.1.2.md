# tiny-magpie 0.1.2 Preview

This release aligns downloads with a subset of the original Magpie matrix:

| Desktop | Download |
| --- | --- |
| macOS Apple Silicon | signed and notarized `.dmg`; drag `tiny-magpie.app` to Applications |
| Windows amd64 / arm64 | unsigned portable `.exe` |
| Linux amd64 / arm64 | unsigned executable; `chmod +x` before launch |

Standalone headless CLI executables remain available for those same five platform pairs (`.exe` on Windows). CLI provides `serve`, `web --no-open`, and scriptable Provider/account, group, key, quota and plugin management. The desktop and CLI continue to share upstream command and gateway logic. Intel macOS, macOS ZIP and Android CLI downloads are omitted.

Both the macOS DMG and the app inside it are Developer ID signed, notarized and stapled; the CLI has Apple's online notarization ticket. Windows requires WebView2. Linux desktop requires GTK 3 and WebKitGTK 4.1 on an Ubuntu 24.04-compatible system (`libgtk-3-0t64`, `libwebkit2gtk-4.1-0`); the CLI/Web build has no desktop library dependency.

The release includes ten downloads, five BUILD JSON files, a macOS NOTARIZATION JSON receipt, MIT LICENSE, UPSTREAM.json and SHA256SUMS. Verify checksums before running; keep LICENSE with redistributed standalone binaries. BUILD evidence binds both executable versions and hashes to clean source; macOS evidence additionally binds the accepted submissions to the final DMG. The published 0.1.1 archives are unchanged.

PR validation now checks native desktop and CLI linked versions and mounts a real unsigned DMG. Release validation additionally checks Apple signatures/tickets and mounts the final signed image. Automated model gateway, Provider/plugin, protocol differential, browser GUI and container gates remain required. The reduced CI introduced after 0.1.1 removes obsolete product tests and runs Windows native regressions on each PR, with the complete retained Windows suite weekly.

This remains experimental. Native Windows/Linux interaction, clean-machine installation, real Provider-account acceptance and Caelis/Bot end-to-end use remain separate [stable acceptance gates](https://github.com/caelis-labs/tiny-magpie/blob/main/docs/compatibility.md#before-a-stable-release). Model, Provider/plugin and routing production code is unchanged in this release; the integrated upstream baseline remains `d783df46cbac9021e26a6bd71ca0b55544552eb2`. Tiny uses independent state and never installs application updates from upstream Magpie.
