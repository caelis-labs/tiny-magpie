# tiny-magpie 0.1.3 Preview

The macOS installer now shows a clear app → Applications drag target with one short hint. A new Tiny bird SVG distinguishes the application, menu-bar icon, control bar, routing hub and favicon from upstream Magpie; native Windows and macOS resources use the same artwork. MIT and upstream copyright notices remain included.

The desktop application now checks **caelis-labs/tiny-magpie's own releases** after startup and every six hours. Settings → General offers Check, automatic checking and preview/stable channels. Preview includes stable releases; stable excludes previews and never downgrades an installed version. Checks do not download or restart. Download stages a new version; Restart to update asks separately and waits for active gateway requests.

Updates require GitHub's SHA-256 digest and exact own repository/tag/platform asset names. macOS uses the same public DMG, verifies the signed app's nonempty matching Caelis team, Tiny bundle ID, version and Gatekeeper, then reuses upstream's staged replacement. Windows/Linux reuse the existing binary replacement/rollback paths and remain unsigned. A package staged under a previous channel cannot be installed after switching channels. Original Magpie update feeds are never used.

A [43-item graded feature review](https://github.com/caelis-labs/tiny-magpie/blob/main/docs/feature-review-2026-10-19.md) compares the running Tiny GUI and upstream snapshot `c483fead`. It separates core Provider/gateway/plugin guarantees from optional presentation, redaction and removed Agent products. Further pruning awaits human review. The integrated upstream baseline is still `d783df46cbac9021e26a6bd71ca0b55544552eb2`; model/Provider/plugin wire behavior and routing implementations are unchanged.

## Install

**Version 0.1.2 needs one manual upgrade to gain the new updater.** Open the Apple Silicon DMG, drag the app to Applications, then launch it there and eject the disk. An app running from a DMG cannot replace itself. Future updates use the Tiny channel. CLI downloads remain supported for the same five platform pairs.

The release matrix stays at 19 assets: Apple Silicon DMG, Windows amd64/arm64 `.exe`, Linux amd64/arm64 executables, five corresponding standalone CLI files, five BUILD records, one macOS NOTARIZATION record, LICENSE, UPSTREAM.json and SHA256SUMS. macOS app/DMG are Developer ID signed, notarized and stapled; the CLI has Apple's notarization ticket. Verify checksums before use. Intel macOS and Android remain outside the matrix.

## Validation

Required release gates run on the exact tagged source. New fixtures cover own-feed and channel boundaries, checks without background downloads, clock shutdown, hash/signature/team/bundle/version rejection, channel-stale candidates, icon consistency and separate restart confirmation. The browser matrix has 42 cases across Chromium/WebKit, five languages and two widths; gateway differential retains 64 bidirectional comparisons.

Local signed-DMG staging was exercised using an existing public signed artifact served over loopback and installed only into a temporary copy. Read-only inspection of the user's running GUI did not replace their live application or change accounts/settings. Native Windows/Linux interaction, clean-machine installation and real Provider-account use remain separate [stable acceptance gates](https://github.com/caelis-labs/tiny-magpie/blob/main/docs/compatibility.md#before-a-stable-release). This remains an experimental release.
